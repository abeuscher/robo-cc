# Session 014 — Tune, Then Launch — Log

**Date:** 2026-09-13
**Branch:** session-014/1
**Roadmap section:** Pass 14 — Tune, then launch

## What was built

The brief's plan was to playtest, tune `Config` by feel through roadmap §7's list, then verify
the Definition of Done and publish. That pass ran, and its actual finding was that fine-tuning
the existing numbers wasn't going to move the game loop forward yet — the game needed a wider
change first, not a narrower one. That finding *is* this session's resolution, not a deferral of
the original plan: it's the reason the session's real work became a set of feature additions plus
two new roadmap passes, rather than a list of retuned constants. Publishing itself (Phase 4) had
already been done by the user before the session opened, to a Friends-only place, independent of
any tuning outcome.

### Rename
- `TitleScreen.luau`: title text "SIEGE" → "OW MY WALLS!", tagline subtitle removed entirely.
  The actual Roblox place name (Studio → Game Settings → Basic Info) is a separate, user-side
  change not touched here.

### Sudden-death overtime
- `MatchController.luau`: the match no longer ends on a tied score at `RoundsPerMatch`. Below
  `RoundsPerMatch` it always advances to another round regardless of score (unchanged); at or
  past it, `shouldEndMatch()` only allows the match to finish once the two scores are actually
  unequal — a tie keeps triggering another round (`swapRoles()`) indefinitely. Refactored the
  score-reading logic in `finishMatch()` into a shared `scores()` helper used by both functions.
- `Hud.luau`: the round-counter label now reads "Sudden death — round N" once `state.round`
  exceeds `Config.RoundsPerMatch`, instead of a confusing "Round 5 of 4".

### Visual/material pass
- `Arena.luau`: parts had no explicit `Material` before (silently defaulting to plain plastic
  despite each having a distinct color). Added a `material` parameter to the local `part()`
  helper; ground → `Grass`, boundary walls → `Cobblestone`, the guard → `Slate`, the build-zone
  and firing-position floor markers → `Neon` (matching the glow already used on projectiles and
  the shield).
- `BlockManager.luau`: wall pieces changed from `Plastic` to `Concrete`, to read consistently
  with the now-Cobblestone boundary walls.

### HUD rework
- `Hud.luau` rewritten. Both panels (the existing bottom-right info block, and a new top-right
  score panel) now sit on a 50%-transparent black, rounded-corner backdrop (`makePanel()`) for
  legibility over the arena.
- New score panel: a stable **Player 1 / Player 2** readout by join order, independent of the
  Builder/Attacker roles that flip every round. Required a new `players` field on the
  `StateChanged` broadcast (`MatchController.seats()`, `Types.Seats`) since nothing previously
  exposed join order to the client — `state.roles` alone isn't stable across a `SWAP`. The
  viewer's own row is highlighted with a tinted background rather than plain text color.
- Info block reorganized to: role, round, phase name, then a single combined progress line
  ("Placing Block X of Y" / "Shot X of Y" depending on phase, replacing two separate
  blocks-remaining/shots-remaining labels), then either **Current Block** (BUILD, Builder only)
  or **Current Weapon** (ATTACK, Attacker only) in the same slot.
- **Current Block** is a small live preview grid (`makeCellGrid`/`setGridFilled`, sized off
  `Config.PieceGridSize`) showing the held piece's actual footprint, mirrored and rotated
  exactly as the Builder has set it with Z/R. Required `BuildInput.luau` to start pushing its
  local rotation/flip/shape state out via a new `Hud.setBuildReadout()` call (mirroring
  `AttackInput`'s existing `setAttackReadout` pattern) — Hud has no other way to see
  client-local rotation/flip state, since only the base shape is ever broadcast.
- **Current Weapon** replaced its text name with a small icon on the same grid widget as the
  block preview (a flat 3-across line for the ballista, a low-high-low arc hump for the
  catapult), so the two "current thing" slots read as the same kind of UI element. The angle
  readout for the catapult stays, now as a separate small label next to the icon.

### Roadmap planning (no code)
- Drafted **Pass 15 — Hidden Flag & Rainbow Wall** in full, as its own session brief
  (`sessions/015. Hidden Flag & Rainbow Wall — Brief.md`): replaces the Princess with a Flag
  that doesn't topple, is hidden from the Attacker (`LocalTransparencyModifier` + aim-assist
  raycast exclusion) until struck by either a projectile or a falling wall piece, but scores the
  Attacker's raised bonus (15 → 20) only on a direct projectile hit; the Builder can reposition
  it once after the wall is confirmed. Bundled with a generated pastel-rainbow wall palette
  (`Color3.fromHSV`, sized to `PieceCount`), colored per placement rather than per body.
- Drafted **Pass 16 — Two-Button Meters & Ballista Elevation** as a roadmap entry (not yet a
  full brief): replaces session 013's oscillating/freeze-click spin meter and the
  previously-sketched ballista elevation control with one shared model — a fixed 3-second
  Up/Down-arrow window (3-2-1 countdown) that auto-fires at whatever value it's left at, applied
  to both catapult spin (a dot above/below a line) and a new ballista elevation control (a
  horizon+fulcrum that lifts proportional to how long Up is held). Also relocates all three
  meters (power, spin/elevation) to the Attacker's left side, persistent (visible at rest) for
  the whole turn, with the power meter's box doubled in height and width at unchanged fill
  timing so it reads as faster without actually being faster.

These two passes are this session's actual answer to "tune, then launch": the pass was run, the
lens needed to widen, and widening it is the work now queued.
