# Session 007 — Fixed Shot Sequence — Log

**Date:** 2026-09-12
**Branch:** session-007
**Roadmap section:** Pass 7 — Fixed Shot Sequence

## What was built

### Phase 1 — `Config`

- Replaced the bare `ShotsPerTurn = 6` with `ShotSequence = { "Catapult", "Catapult",
  "Ballista" }`; `ShotsPerTurn` now derives as `#ShotSequence` so the two can never drift apart,
  the same pattern `BlockCount` already used for `BlockTypes`.

### Phase 2 — `MatchController` — the current shot's weapon

- Added a `currentWeapon()` reader: `nil` outside `ATTACK`, else
  `Config.ShotSequence[#Config.ShotSequence - state.shotsRemaining + 1]` — the shot index counts
  up as `shotsRemaining` counts down. Verified by hand against all four turn points (fresh
  ATTACK, after shot 1, after shot 2, after shot 3) and it lands on Catapult / Catapult /
  Ballista / nil correctly. Broadcast as `currentWeapon` on `StateChanged`; exposed as
  `MatchController.currentWeapon()` for `WeaponManager`.

### Phase 3 — `WeaponManager` — server dictates the weapon

- `onFireWeapon` no longer reads or validates `payload.weapon` at all. It reads
  `MatchController.currentWeapon()` before calling `consumeShot()` (which is what advances the
  shot index), and fires whatever that returns — the client's request no longer carries a
  weapon at all.

### Phase 4 — `Types`

- `ShotPayload` dropped its `weapon` field.
- `StatePayload` gained `currentWeapon: Weapon?`.

### Phase 5 — Client (`AttackInput`, `Hud`)

- `AttackInput` dropped the `F` key handling entirely. `state.weapon` mirrors
  `StateChanged.currentWeapon` instead of free-toggled local state. This mirroring had to move
  out from under the activation-transition early return in `update()`, since the sequence
  switches weapon mid-turn (Catapult → Ballista between shot 2 and shot 3) without any phase or
  role transition — the existing "only act on `shouldBeActive ~= active`" shape would have
  missed that switch entirely.
- `releaseSwing`'s outgoing `FireWeapon` payload dropped `weapon`.
- `Hud`'s attacker hint line dropped "F weapon."

## Playtest result

Two-player Studio playtest. User's assessment: "Okay looking good" — the Attacker got exactly 3
shots in the fixed Catapult / Catapult / Ballista order, no way to switch out of turn, and the
HUD/prop model tracked the mandated weapon correctly throughout, including the mid-turn switch.
No defects reported.
