# Session 006 — Piece Queue — Sequential Hand-off — Log

**Date:** 2026-09-11
**Branch:** session-006/1
**Roadmap section:** Pass 6 — Piece Queue (Sequential Hand-off)

## What was built

### Phase 1 — `Config` / `Arena` cleanup

- Removed `PILE_MARGIN`/`PILE_GAP`/`PILE_Z` and the per-type `PileOrigin` math entirely --
  nothing is pre-spawned into a pile anymore, so there was nothing left to space out.
  `PlatformSize` now just covers the build zone plus a `PLATFORM_MARGIN` (5 studs), which
  shrank the platform since it no longer has to reserve room for a pile.
- `Arena.build()` lost its per-type pile-marker loop.

### Phase 2 — `BlockManager` — issue on demand

- Replaced pre-spawning with a queue built from `Config.BlockTypes` (one entry per `Count`,
  flattened in order). `resetQueue()` (replacing `spawnAll()`) destroys last round's blocks and
  rebuilds the queue; `currentTypeDef()`/`remainingCount()` expose queue state to
  `BuildManager`; `placeCurrent(centre, rotation, flipped)` builds a piece's `UnionOperation`
  and places it in one step, since nothing physical exists before placement.
- `releaseAll()` simplified — every entry in `placedParts` was placed through `placeCurrent()`,
  so the old "destroy if never placed" branch had nothing left to do and was removed.
  `get()`/`moveToWall()`/`returnToPile()` are gone; nothing looks a block up by id anymore.

### Phase 3 — `BuildManager` — sequential validation, no undo

- `PlaceBlock`'s payload dropped `blockId` — the server always knows the Builder's current
  piece via `BlockManager.currentTypeDef()`, so there's nothing for the client to choose.
  Occupancy entries simplified from blockId-keyed to plain booleans, since nothing ever needs
  to release a specific block's cells again.
- Settled at the Open Gate: undo removed entirely ("I think that makes it more interesting" --
  the user's call, not a default), and Confirm Wall can be pressed at any time — the latter
  needed no code change at all, since `MatchController.confirmBuild` never checked queue state
  to begin with.
- `PickupBlock` deleted outright: the handler, its `Remotes.luau` entry, and `releaseCells()`.

### Phase 4 — Client

- `BuildInput` lost the pile-click/lift/return flow and `blockUnderRay` entirely. The Builder
  now auto-holds the current piece as soon as `blocksRemaining.LPiece > 0` (read off the
  existing `StateChanged` broadcast — no new remote needed since the shape stayed static this
  session). `Hud`'s builder hint updated to match.
- One-line touch outside the brief's file list, anticipated by the brief itself:
  `MatchController.startRound()`'s call site changed from `BlockManager.spawnAll()` to
  `BlockManager.resetQueue()`.

### Follow-up — mirror/flip (`Z`)

Requested after the queue playtest: since `R`'s 4-state rotation already covers every turn
about the Z axis, "flip on Z" was interpreted as a **mirror** — a reflection no rotation can
reach (an L-piece's mirror is a J-piece). Added `GridUtil.mirrorShape` (sharing a new
`normalizeShape` helper with `rotateShape` to avoid duplicating the bounding-box
re-normalization). The mirror has to happen at the geometry level — `BlockManager.placeCurrent`
takes a `flipped` flag and builds the union from the mirrored cell list directly, since a rigid
`CFrame` rotation can never produce a shape's mirror image on its own. `BuildManager` validates
occupancy against that same mirrored shape. Client-side, `Z` toggles a `flipped` state that
composes with `rotation` through a `baseShape()` helper; both reset after each placement and on
deactivation. `Types.PlacePayload` gained `flipped: boolean`. `Hud`'s hint updated again.

## Playtest result

Two-player Studio playtest covering both the queue-based hand-off (no pile, forced sequential
placement, all 4 rotations) and the follow-up mirror/flip feature. User's assessment: "Great.
Much better" after the queue change, and reported happy with the rest of the playtest once the
flip was added too — no defects reported for either.
