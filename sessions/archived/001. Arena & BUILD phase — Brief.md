# Session 001 — Arena & BUILD phase — Brief

**Roadmap section:** Pass 0 (skeleton, folded in) + Pass 1 — BUILD phase, end to end (`roadmap.md`)
**Branch:** session-001

## Goal

Stand up the config/arena foundation, then implement the entire BUILD phase: two players
join and see their role, the Builder sees the arena and the Princess, places 12 anchored
blocks on a grid with pickup/re-place, and confirms — after which the state machine advances
to `ATTACK` and holds. No weapons, no physics, no unanchoring yet.

## Plan

### Phase 1 — Shared foundation

- `src/shared/Config.luau` — one table with every tunable from spec's "Tunable constants
  module" (block dimensions, mass, friction, restitution; block count 12; Princess distance;
  gap width; ballista muzzle velocity + gravity scale; catapult min/max force + angle range;
  shots per turn 6; rounds per match 4) plus the roadmap additions: `GridSize`,
  `BuildZoneSize`, `MovingBlockKillSpeed`, `ProjectileLifetime`, `CatapultImpact`. Use the
  spec's stated defaults.
- `src/shared/Types.luau` — `Phase` (`"BUILD" | "ATTACK" | "RESOLVE" | "SWAP"`), `Role`, and
  the shot-payload shape (defined now, used later).
- `src/shared/GridUtil.luau` — world position ⇄ grid cell, and snap-to-cell, given the build
  zone origin and `Config.GridSize`.
- Delete `src/shared/Hello.luau`.
- Extend `Remotes.luau` with the BUILD-phase events: `PlaceBlock`, `PickupBlock`,
  `ConfirmBuild`, `StateChanged`.

### Phase 2 — Arena & Princess (server)

- `src/server/Arena.luau` — build the static geometry from `Config` into a
  `Workspace.ActiveRound` folder: Builder platform with a visibly marked build zone;
  Attacker firing position across the gap at matched ground elevation; the Princess dummy
  (a plain part, named `Princess`) at `Config.PrincessDistance` behind the build zone.
  `Arena.reset()` clears the folder. Plain grey parts — no styling.
- Called once at server start this session. The per-round reset loop comes later.

### Phase 3 — State machine & roles (server)

- `src/server/MatchController.luau` — wait for 2 players; assign Builder/Attacker by join
  order; broadcast `StateChanged { phase, roles, blocksRemaining, round }`. Run a single
  BUILD phase; on `ConfirmBuild` from the Builder, set `phase = "ATTACK"`, broadcast, and
  hold (no attack logic yet).
- `src/server/init.server.luau` — replace the smoke-test body with `Arena.build()` and
  `require(MatchController).start()`.

### Phase 4 — Block placement (server + client)

- `src/server/BlockManager.luau` — spawn one anchored block `Part` with `PhysicalProperties`
  from `Config`; track the live block list; enforce the 12-block budget. No unanchor / no
  `SetNetworkOwner` this session.
- `src/server/BuildManager.luau` — handle `PlaceBlock` (validate: requester is Builder, cell
  inside build zone, cell free, budget remaining → spawn), `PickupBlock` (validate: block
  exists, requester is Builder → despawn, free the cell), `ConfirmBuild` (validate:
  requester is Builder → notify `MatchController`). Grid occupancy is authoritative here.
- `src/client/BuildInput.luau` — mouse hover → snapped translucent ghost block within the
  build zone; click an empty cell → `PlaceBlock`; click own block → `PickupBlock`;
  on-screen Confirm button → `ConfirmBuild`. Active only while `phase == "BUILD"` and the
  local player is the Builder.

### Phase 5 — HUD

- `src/client/Hud.luau` — role banner ("You are the Builder" / "…the Attacker"), current
  phase label, blocks-remaining counter (BUILD), and a "waiting for the other player"
  state. Driven entirely by `StateChanged`.
- `src/client/init.client.luau` — after Start, hand off from the title screen to `Hud` +
  `BuildInput`, both fed by `Remotes.StateChanged`.

## Out of scope

- `PrincessMonitor`, kill detection, RESOLVE, SWAP, scoring, the round loop, `MatchResult` —
  the win/loss session (Pass 3).
- Attacker input, `AimViz`, tuning.
- Any visual polish. Grey parts are the target.

## Process rules

- Read every file you intend to modify before editing it.
- All game state is server-authoritative. Clients send intent only; the server validates
  role, phase, and limits on every remote.
- Every tunable lives in `src/shared/Config.luau`. No gameplay magic numbers in logic.
- One ModuleScript per responsibility. `init.*.luau` scripts only bootstrap.
- `src/shared` never requires from `src/server` or `src/client`.
- Match the existing code style. No comments or type annotations on code you did not write.
- Adapt silently to small drift between this brief and the code; note it in one line. Pause
  and ask only for decisions that are expensive to reverse — data shape, new abstractions,
  changes to the arena or physics model.
- A question from the user is a question, not an instruction to act.
- When implementation is done: sync in Studio, run a two-player playtest, report what you
  saw. Then stop — do not start the close until the user says so.
